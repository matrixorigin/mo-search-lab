# 运行环境与配置采集

## 范围

`run` 自动保存环境证据；`inspect` 只读 SQL 元数据并生成环境报告，不建库或加载数据。仍为独立静态二进制，不引入 MO 内核、Docker、kubectl 或 Python 运行依赖。

## 来源与含义

- SQL：已有 `VERSION()`，加构建时间、Git 提交、选定会话默认变量与 `SHOW BACKEND SERVERS`。后者受租户、路由及权限影响，仅表示账号可见 CN，不推断完整 CN/TN 拓扑。探测失败单独记为 unavailable，不影响性能断言。
- SQL 节点配置：`mo_catalog.mo_configurations` 提供 HAKeeper 收到的节点配置快照与默认值。筛选 FileService 缓存、内存上限等允许字段，单独保存上报节点。与账号可见 CN、文件显式配置、物理资源配额、实时使用量分开；不承诺完整拓扑、动态修改后的值或缓存实际启用。服务端筛选后再次检查字段白名单，最多 256 个节点和 2048 行配置，空结果或超限降级为 unavailable。
- 客户端：Go OS/架构、可用逻辑 CPU、主机名；始终与 MO 服务分开展示。
- `--environment-file`：受限 JSON 描述客户声明的部署、资源配额及节点，保留输入 SHA256；不会覆盖 SQL 证据。
- 可重复 `--mo-config`：实际提供的 TOML 文件，保留文件 SHA256、节点标识、FileService 缓存容量和选定内存参数。只提取允许字段，不复制配置原文或凭据；跳过 ETL、TMP 和 Iceberg。未配置容量不假定默认值；文件值不证明运行进程已加载。MO ByteSize 的 MB/GB 按二进制单位解释。
- `--monitoring-config`：Prometheus 或 Grafana 的只读 Prometheus 代理，显式提供目标 scope、PromQL 与单位。Grafana 可发现唯一或唯一默认的 Prometheus 数据源；有歧义时要求 UID。Token 仅从环境变量读取，不序列化。

## 测量与边界

监控 range 查询在性能测量结束后进行，时间范围为查询阶段（包含计划与预热），不增加计时内请求。不连监控时无需网络访问。采集有超时、响应大小、查询/series/样本上限；失败、空结果及非有限值不能作为 0。失败与部分采集明确保留。

人工输入语法与监控配置在 SQL 连接、建库前校验；不支持的 SQL 可降级。`report.json.environment` 和新运行的 `environment.json` 保存相同证据，HTML/CLI 离线展示。旧报告缺少字段仍可读，重渲染不修改原始 JSON。

## v0.9.2 信息组织

环境视图按版本与部署、节点与缓存、检索参数、资源监控分区。缓存按节点/存储服务对齐；默认值、文件显式值、逻辑内存限制、文件身份、客户端信息和采集原因采用展开呈现。网页与 CLI 使用同一个 presentation；CLI 的 `e` 和 `--environment-details` 控制详情。

SQL 筛选使用服务名称与同一节点的配置路径关联，排除 ETL/TMP，不假定数组索引。Iceberg 不在查询与 TOML 提取白名单中。历史记录应用同样的展示筛选，原始档案保留。节点配置注明启动快照与上报时间未知，磁盘容量字段不被解释成缓存实际启用。

## 验证

SQL mock 覆盖可见节点、上报配置及权限失败；配置解析覆盖白名单、凭据排除、空值、零值、重复/异常数据与响应上限。TOML 覆盖数组表、缺省/零容量、单位与凭据排除；HTTP fixture 覆盖 Grafana 数据源发现、range 参数、认证、失败/超时/空值及响应上限；报告覆盖来源分离、当前/默认值、未知值、离线图和旧报告兼容。使用已有 MO 4.2.1 fixture 做 `inspect` 和 smoke 集成验证。

## v0.9.3 配置精简

SQL 白名单与 TOML 提取均移除跨节点缓存开关。网页与 CLI 不再显示此项；读取历史 JSON 时仍兼容旧字段，重渲染不修改原始记录。

## v0.9.4 同配置节点合并

网页与 CLI 的缓存表和配置默认值表按节点角色与原始配置值合并，显示节点数量及每节点容量。不同值保留为不同分组，不累加容量；UUID、SQL 地址、原始 JSON 仍按节点保留。容量比较使用原始字节值，不用舍入后的展示值。

## v0.9.5 缓存名称与检索参数

内存缓存、Metadata 缓存、磁盘缓存统一命名。Metadata 配置按节点合并展示，零值表示使用默认容量，不解读为关闭或实际 0 B。TOML 支持显式 metacache.memory-capacity，SQL 与文件的来源和差异分别保留。

只读 SQL 追加 IVF 训练、HNSW 线程/容量、Pre-filter/Auto 初始会话变量，按四类展示。旧服务未返回的变量与历史未采集的值不填充；具体索引参数与运行场景覆盖仍需核对其 DDL/SQL。

## v0.9.6 Metadata 环境默认容量

环境声明支持独立的 system_memory_total_bytes / system_memory_source，单机顶层值需要 scope，多节点用节点角色与 UUID 关联；资源 limit 和客户端内存不参与默认容量计算。按已核对的 MO 发布版本/提交选择默认规则，未知版本或缺少内存依据不猜测数值。

Metadata 的零值、TOML 缺省与显式容量分别处理；主要缓存表和配置默认值列展示环境推算容量与内存档位，快照列保留零配置含义，原始记录不修改。不同节点的环境默认值不同则分别展示；相同容量合并但不相加。验证覆盖档位边界、缺少依据、未知版本、显式配置优先、TOML 缺省、不同节点容量与来源分离。

## v0.9.7 环境诊断信息精简

底部统一为一个诊断详情，保留非 Working CN、配置差异、SQL 采集失败。配置差异按原始值比较，排除文件缺省和 Metadata 默认推算的展示差异；遇到舍入掩盖差异时展示精确字节。诊断表有文件证据时才出现文件列。

非 Working CN 的状态在概览提示，完整 UUID/IP 及来源证据保存在原始记录。纯环境检查隐藏客户端；性能报告保留简短的压测客户端信息。逐节点硬件配额改为按角色和相同配置合并的每节点摘要，不累加。网页与 CLI 保持同一视图，重渲染不更改原始记录。

## v0.9.8 性能与环境 Tab

性能 HTML 分为性能测试与运行环境两个 Tab，默认展示图表；环境 Tab 直接展示四个分区和可展开的诊断详情。两个视图来自同一次运行的原始记录，历史未采集环境时明确说明。只读 `inspect` 保持独立页面。

控件支持键盘切换、URL 锚点、离线 HTML、打印及无脚本阅读。Tab 样式、控制脚本和环境内容使用稳定的元素 ID，供准备阶段的汇总发布脚本复用；不依赖会被 Go html/template 移除的源码注释。引用独立检查的汇总页标明来源和采集时间，不将其配置绑定到其他性能测量。

验证覆盖原始记录不变、历史兼容、汇总重复发布及错误输入不覆盖页面；浏览器核对点击/键盘/锚点切换、数据集导航、原始 JSON 链接、手机布局、离线打开、打印与无脚本阅读。
